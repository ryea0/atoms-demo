# PRD：轻量待办事项应用（Todo）

> 版本 v1.0　作者：产品经理（PM）　状态：已评审
> 一句话需求：做一个能记录、勾选、删除待办的简洁应用。
> 阅读说明：F=功能编号、US=用户故事编号、AC=验收标准编号；下游角色按编号对齐，勿凭印象改语义。

## 1. 背景与目标

用户需要一个零门槛的待办清单：打开即用、无需注册登录、数据一眼可见。
本期目标是跑通「新增 → 勾选完成 → 删除」的主闭环，界面清爽、加载快、手机上也好用。
成功的衡量标准：新用户 10 秒内完成第一笔待办的新增与勾选，无需任何引导说明。

## 2. 目标用户与使用场景

- 个人用户：记购物清单、今日三件事、临时备忘。
- 主场景（P0）：地铁上单手掏出手机 → 输入一件事 → 回车 → 办完勾掉。
- 次场景（P1）：睡前清理清单，把不再需要的条目删掉。

## 3. 范围

**本期做**：单清单、单用户的增/查/勾/删 + 进度统计。
**本期不做**：多清单与分组、账号体系与云同步、截止日期/提醒/重复任务、附件与备注、排序拖拽、多语言。

## 4. 功能清单

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| F1 | 新增待办 | P0 | 输入标题后回车或点「添加」即创建；标题去首尾空白，非空校验 |
| F2 | 待办列表 | P0 | 倒序展示（新的在上）；空列表显示引导文案与示例 |
| F3 | 勾选完成 | P0 | 点击复选框切换完成态；完成项划线置灰但不消失，可取消勾选恢复 |
| F4 | 删除待办 | P1 | 每项右侧删除按钮；删除即时生效，无需二次确认（条目可重建） |
| F5 | 进度统计 | P2 | 顶部固定显示「已完成 x / 共 y」；全清空时显示鼓励文案 |

## 5. 用户故事

- US1：作为用户，我想快速记下一件事，以免转头就忘。
- US2：作为用户，我想勾掉已完成的事，获得推进感。
- US3：作为用户，我想取消勾选，因为发现事情还没做完。
- US4：作为用户，我想删除不再需要的条目，保持清单干净。
- US5：作为移动端用户，我想在手机上单手完成以上全部操作。

## 6. 交互与界面要点

- 单列布局，移动优先；内容区最大宽度约 640px 居中，避免大屏拉伸。
- 新增入口固定在列表上方：全圆角输入框 + 黑色圆形「添加」按钮，回车等同点击。
- 条目为卡片式：左侧复选框、中间标题、右侧删除按钮；完成态 `line-through` + 置灰。
- 反馈即时：新增/勾选/删除后列表与统计同步刷新，无加载态（本地内存操作）。
- 触控目标 ≥ 44px；错误提示（空标题）就地展示在输入框下方，不用弹窗。

## 7. 验收标准

- AC1（对应 F1）：空标题或全空白标题提交时不创建条目，并就地提示「请输入内容」。
- AC2（对应 F1）：新增后新条目立即出现在列表顶部，输入框清空并保持焦点。
- AC3（对应 F3）：勾选后条目划线置灰，顶部计数 +1；取消勾选后恢复且计数 -1。
- AC4（对应 F4）：删除后条目从列表消失，计数同步更新。
- AC5（对应 F2）：无任何条目时显示引导文案「今天想做点什么？」与一条示例。
- AC6（对应 F5）：计数恒等式「已完成 + 未完成 = 共 y」在任意操作后成立。

## 8. 非功能需求

- 首屏可交互 < 1s；操作响应即时（< 100ms，无网络等待）。
- 移动端可用：触控目标 ≥ 44px、输入不触发页面缩放、单手可达。
- 零依赖安装、零配置即可运行；界面在主流现代浏览器（Chrome/Safari/Edge 最新版）表现一致。

## 9. 数据与运行边界

- 数据为内存态：刷新页面回到初始演示数据，本期不做持久化（运行环境为浏览器沙箱，禁用 localStorage/cookie）。
- 单用户单清单，无并发编辑场景；条目数量上限按 200 条设计，超出仅做性能预期说明，不做分页。

## 10. 里程碑与开放问题

- M1（本期）：主闭环 F1-F3 + 空态；M2：F4/F5 与移动端打磨。
- 开放问题 O1：是否需要「全部清除已完成」？（待下一轮评审，不阻塞本期）
- 开放问题 O2：完成条目是否折叠？（待用户反馈，本期不折叠）
